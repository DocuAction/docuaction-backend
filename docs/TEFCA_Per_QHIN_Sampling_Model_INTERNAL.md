## 2. The defect found and fixed

`CochranSampler.draw_sample` with strata computes **one sample size from the
whole population** and allocates it across strata by proportional
largest-remainder. That is correct for a confidence statement about the
population as a whole. It is **wrong when confidence is required of each
stratum**.

Measured against the delivered population — 23,562 promoted records, 11 QHINs,
95% / ±5% / p=0.5 with FPC:

| | National, proportionally allocated | Per-QHIN independent |
|---|---:|---:|
| Total sample | **379** | **1,967** |
| Largest QHIN (N=10,481) | 169 | 371 |
| N=88 QHIN | 1 | 72 |
| N=44 QHIN | 1 | 40 |
| **N=3 QHIN** | **0** | **3 (census)** |

A three-record QHIN received **zero** selected records while the total still
read as a 95% sample. That is the failure the contract's "from each QHIN"
language exists to prevent.

**The formula was not changed.** `draw_per_stratum` calls the same
`calculate_sample_size`, with the same Cochran arithmetic and the same finite
population correction. What changed is *what it is applied to*. `draw_sample`
was left exactly as it was — it answers a different question and has its own
callers and tests.

Corroboration: the methodology document independently records "Two QHINs have 44
and 3 records", which matches the measured strata exactly.

## 3. Design

**Per-stratum RNG.** Each stratum draws from `Random(f"{seed}:{stratum}")`
rather than one shared generator. With a shared generator a stratum's selection
depends on how many were drawn before it, so **adding a QHIN would silently
re-draw another QHIN's sample**. Certified by test.

**Census disclosure.** `stratum_sizing[key]["census"]` is True where n reaches
N. The approved methodology requires this to be disclosed, not hidden inside a
total.

**Seed.** Generated by `random.SystemRandom()` when absent and always returned,
so any draw is reproducible. Never derived from the clock — a clock-derived seed
is guessable and a sample could be steered. Certified by test.

**Reproducibility.** `SampleResult.config()` returns population size, sample
size, confidence, margin, proportion, FPC flag, seed, strata config, per-stratum
distribution and per-stratum N/n — everything needed to redraw or check the
selection.

## 4. Persistence

**SAMPLING PLAN: PERSISTED · SAMPLE MEMBERSHIP: PERSISTED — and both already
existed.**

`ReviewSample` stores population_size, sample_size, confidence_level,
margin_of_error, proportion, use_fpc, **random_seed**, rule_set_version,
strata_config, strata_distribution, status, drawn_at, created_by.
`SampleEntity` stores membership with its `stratum` and review status.

Unlike the monthly delta, an official sample **must** be frozen: a random
selection recomputed on each request would not be the same sample. The existing
models already provide that.

**Migration required: NO.**

## 5. The operational path — Step #13B

Step #13 delivered the **statistical core** and left one blocker: nothing wired
`draw_per_stratum` to a plan. `app/tefca_registry/qhin_sampling.py` is that
wiring, and it contains **no formula** — the statistics stay in
`sampling_engine`.

```
current delivery
  -> eligible population        (curated records for the delivery)
  -> QHIN resolver              (canonical `managed_by_qhin` edge, exactly one)
  -> draw_per_stratum           (one Cochran call per QHIN)
  -> ReviewSample + SampleEntity (frozen membership, `uq_sample_entity`)
  -> review_records -> analyst -> independent QA
```

| Concern | How it is settled |
|---|---|
| Plan identity | `plan_key` — source, delivery, review type, confidence, margin, proportion, FPC, HELD flag. Anything that changes what the sample MEANS is in the key |
| Idempotence | a second `finalize_plan` with the same key returns the plan already drawn, with its original seed — it never redraws |
| Concurrency | `pg_advisory_xact_lock(hashtext(plan_key))`, transaction-scoped, plus `uq_sample_entity` beneath it |
| Client control | there is no parameter for entity ids, membership or QHIN assignment. Selection is server-side or it is not a sample |
| Reads | `get_plan` reads storage. It cannot redraw because it never calls the sampler |
| Completion | derived from `review_decision_events`, not a status kept in parallel. Selection is not completion |
| Provenance | `sampling_plan_finalized` audit row carries plan key, algorithm, seed, sizes and stratum count |

**`draw_sample` is not reachable from this path**, and a test asserts the module
never calls it. The legacy `POST /samples` route is unchanged and still answers
the national/proportional question; it is not the official per-QHIN path.

**Migration required: NO.** Both tables already existed.

### The limit this gate exposed

`sample_entities.entity_id` is a NOT NULL foreign key to a canonical entity, so
**a record that was never promoted cannot be a sampling unit**. On the delivered
population all four HELD records are also unpromoted — so `include_held=True`
changes nothing there, and the eligible population is 23,562 either way.

The resolver used to filter those records out in the query. It now returns them
as UNRESOLVED with a stated reason, because a record dropped before anyone
counts it is the one nobody asks about. 23,562 eligible + 4 unresolved = 23,566
delivered, and the accounting closes.

Whether HELD records *should* be sampleable is §7 question 1 and remains open.
Nothing here promotes a HELD record to make it sampleable.

## 6. Population and eligibility — what is settled and what is not

| Category | Status |
|---|---|
| Frame | delivered records partitioned by managing QHIN — **APPROVED** |
| QHIN assignment | `org_managing_org`, promoted to the canonical entity; **0 records unassigned** in the delivered population |
| Promoted records | eligible — 23,562 |
| NEW / CHANGED / UNCHANGED | delta status does **not** drive sampling eligibility; all remain eligible. Sampling asks a different question from Step #12 |
| HUMAN_REQUIRED overlap | a record may be both sampled and HUMAN_REQUIRED; exception review does **not** discharge a sampling requirement |
| **HELD (4 records)** | **UNRESOLVED** — see §7 |
| NOT_PRESENT_IN_CURRENT_DELIVERY | not in the current delivery's frame; historical sample membership stays immutable |
| Test-pattern records (9) | **UNRESOLVED** — depends on the standing ONC population-scoping question |

**Census screening is not a sample.** The methodology is explicit: AGT screens
100% operationally, but "screening everything does not discharge a sampling
requirement", and the retrospective report will not claim it does.

## 7. Genuine methodology questions arising

Only two, and both are operational policy the code cannot settle:

1. **HELD eligibility.** Are the 4 HELD records inside or outside the sampling
   frame? They are delivered records that have not been promoted. Neither
   "automatically excluded" nor "automatically selected" is supported by current
   methodology text.
2. **Repeat-selection policy across periods.** Whether an organisation sampled in
   one period may, must, or must not be eligible in the next. Undefined; random
   selection currently treats each period independently.

Both are recorded, neither is answered. The two already-known unresolved
parameters (margin of error, stratification confirmation) remain open per §1.

**The 95% confidence level was not reopened.**

## 8. Performance

Sizing is one `calculate_sample_size` call per stratum — 11 calls for the
delivered population, not 23,562. Selection is one `random.sample` per stratum
over an in-memory list. Grouping is a single pass.

**O(N) in records, O(S) in strata.** No pairwise comparison, no per-record
database call, no external API call.

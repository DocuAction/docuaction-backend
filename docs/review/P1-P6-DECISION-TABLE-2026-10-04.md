# P1–P6 decision table (2026-10-04, R27-7)

not left implicit.

**The one distinction every row depends on:** a check's own OUTCOME
(did the source answer, and what did it say) is a different fact from
whether that outcome makes an entity's overall record COMPLETE, which is
a different fact again from the entity's CLASSIFICATION (B1–B4) and
REPORTABLE status. An unavailable check is never counted as a successful
check; the three facts are tracked and displayed separately (confirmed
again this round: `tests/test_verification_completeness_2026_10_04.py`,
unchanged, pass). None of P1–P6 asks whether to merge these three facts
back together — all six only ask where the LINE should sit, with the
facts kept separate either way.

in the workbook already says so and marks the case Blocked without it —
see `DocuAction_Integrated_QA_Workbook_v4_2026-10-04.xlsx`.

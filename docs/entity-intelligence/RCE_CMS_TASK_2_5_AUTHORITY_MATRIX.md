# RCE / CMS evidence — Task 2–5 authority matrix

Four authority questions per capability, kept apart: (1) what the executed contract requires (layer 1, from the traceability matrix in `docs/cor_activation_package/01_Contract_Traceability_Matrix.md`); (2) what the submitted Task 2 methodology draft says (layer 2, **awaiting written COR acceptance** — D2 unaccepted); (3) what current RCE governing material says (layer 4); (4) what this branch can do (isolated, feature OFF). Nothing below changes the methodology or the frozen Task 1–6 code.

## Contract baseline (layer 1, as recorded in the repo)

- Task 2: a COR-accepted protocol aligned to the Common Agreement, QTF and SOPs, with accuracy evaluation approaches, stratification/prioritisation, a discrepancy taxonomy and sampling methodology.
- Task 3: retrospective review of a ≥95%-confidence sample per QHIN within 120 days; information "may come from publicly available data, contractor-owned data, data provided by the COR, and any other relevant sources".
- Task 4: bi-weekly review of a representative sample of **new submissions** (solicitation Q&A: new entrants only).
- Task 5: COR-directed priority reviews (~20/month anticipated), deadline set per request; status reports must include the issue, root cause if determined, severity/impact, recommendations, resolution.

## Decisions this matrix isolates

- **COR acceptance required for**: explainable-variation as a taxonomy refinement; any participation-dimension rule; provider-type CMS files; IQVIA; Google; state registries; SAM credential (D4); D4_ADDRESS_MATERIALITY.
- **Reusable Core that changes no methodology**: the observation/provenance model, normalisation, the comparison signals, deltas with scope, the assessment vocabulary, the rule-version register, absence semantics, the read-only CMS adapter design. All of it produces analyst context; none of it produces a category.
- **Must wait for the IQVIA file**: everything IQVIA.
- **Should not be built**: a PECOS connector (no public API; NPPES-proxy confusion already recorded), a second PPEF downloader, a policy engine that evaluates entities against rule text, any automated category.

## Findings that shape the design

1. **PPEF is enrollment-level, not organisation-level.** Everything hangs off ENRLMT_ID; PECOS_ASCT_CNTL_ID is the only cross-enrollment "same entity" key and "maps closely to … an EIN for an organization" (data dictionary) — which puts it near the program's EIN/TIN exclusion. Use it as an opaque link key only, never displayed as a tax identity.
2. **The PPEF practice-location file has no street line.** Locality-level corroboration only; the frozen methodology already labels PPEF address agreement as city/state/ZIP.
3. **DBA exists in the provider-type files (hospital, FQHC, RHC, hospice), not in PPEF.** A second-source DBA corroboration is possible only for those provider types — which is exactly the population where Tier 2 CMS-directory vetting evidence points.
4. **Cadence differs**: Hospital Enrollments monthly; PPEF and the other provider-type files quarterly. Quarterly data supports retrospective corroboration (Task 3) and priority reviews (Task 5); it is weak for bi-weekly change detection (Task 4) unless the change being detected is in the delivery, not in CMS.
5. **The RCE now cites the PPEF page as Tier 2 vetting evidence** (Vetting SOP v2.0 Appendix 1, until 2026-12-31). That makes "does this entity appear in PPEF" a question the program will be asked about — and one whose absence semantics matter.
